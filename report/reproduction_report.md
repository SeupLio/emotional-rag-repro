# Emotional RAG 复现差异分析报告

**论文**：Le Huang, Hengzhi Lan, Zijun Sun, Chuan Shi, Ting Bai.
*Emotional RAG: Enhancing Role-Playing Agents through Emotional Retrieval*.
arXiv:2410.23041（2024-10-30）。

**复现工程**：`emotional-rag-repro`（本地 RTX 3060 Laptop 6 GB，单卡，无 LLM API）。
**复现日期**：2026-09。
**复现范围**：InCharacter 数据集上的 BFI / 16Personalities（MBTI）人格一致性评测，
五种检索策略 + 一条本文新增的语音声学情感通道（多模态扩展）。

---

## 0. 一句话结论

> **检索框架与评测协议完整复现，绝对数值无法对齐。**
> 情感检索（Emotional RAG）的**机制**——语义通道 + 情感通道、五种融合策略、Plutchik
> 8 维情感向量——可以在本地完整跑通并且策略之间存在可区分的差异；但把骨干从
> GPT-3.5 / Qwen1.5-72B / ChatGLM3-6B 换成 **Qwen2.5-1.5B-Instruct** 之后，人格评测的
> 绝对精度显著低于论文，**这是本次复现最大的、也是唯一量级上的差异来源**。
> 多模态扩展（语音声学通道）在真实情感语音上有效，但在中性 TTS 合成语料上信息量不足。

## 1. 论文做了什么（复现目标）

角色扮演智能体的关键是如何利用角色记忆。传统 RAG 只按**语义相似度**检索记忆，
Emotional RAG 受心理学**心境依存记忆（Mood-Dependent Memory）**理论启发，额外引入一条
**情感相似度**通道：

1. **情感建模** `G`：把查询和每条记忆映射为 Plutchik 情感环的 8 维向量，每维 1–10 分
   （joy / acceptance / fear / surprise / sadness / disgust / anger / anticipation）。
2. **语义编码** `F`：bge-base，768 维。
3. **情感检索** `M`：五种策略把两条通道合起来排序，取 Top-10 注入 prompt。
   - `ordinary`：仅语义（基线）。
   - `C-A`（组合-加）：`d_sem + d_emo`。
   - `C-M`（组合-乘）：`d_sem × d_emo`。
   - `S-S`（序贯-语义优先）：先按语义取候选池，再按情感重排。
   - `S-E`（序贯-情感优先）：先按情感取候选池，再按语义重排。
4. **评测**：让角色智能体作答 BFI（44 题，1–5）与 16Personalities（60 题，1–7），
   与人格数据库真值比对，指标为 `Acc(Dim)` / `Acc(Full)` / `MSE` / `MAE`，
   其中 H/L/X 分带由人群均值 ±0.5σ 决定。

**论文在 InCharacter 上的主要结果（Table II，32 个角色）**：

| 骨干 | 方法 | BFI Acc(Dim) | BFI Acc(Full) | BFI MSE | BFI MAE | MBTI Acc(Dim) | MBTI Acc(Full) | MBTI MSE | MBTI MAE |
|---|---|---|---|---|---|---|---|---|---|
| ChatGLM3-6B | Ordinary | 0.6242 | 0.1250 | 0.1849 | 0.3728 | 0.6694 | 0.2188 | 0.1526 | 0.3610 |
| ChatGLM3-6B | Emotional RAG | **0.6369** | 0.0938 | **0.1720** | **0.3625** | 0.6694 | **0.2812** | 0.1539 | 0.3655 |
| Qwen1.5-72B | Ordinary | 0.6815 | 0.0938 | 0.1433 | 0.3024 | 0.7438 | 0.3438 | 0.1230 | 0.2920 |
| Qwen1.5-72B | Emotional RAG | **0.7261** | **0.2500** | **0.1269** | **0.2878** | **0.7934** | **0.4688** | **0.1156** | **0.2900** |
| GPT-3.5 | Ordinary | 0.7006 | 0.1875 | 0.1496 | 0.3121 | 0.7851 | 0.5000 | 0.1221 | 0.2965 |
| GPT-3.5 | Emotional RAG | 0.7006 | 0.1875 | **0.1475** | **0.3082** | 0.7851 | 0.4375 | 0.1236 | **0.2927** |

## 3. 复现结果与差异

### 3.0 一个必须说明的前提：语言不对称

本次复现出现明显的**语言不对称**，直接决定哪些结果可解释：

- **中文角色（6 个，Genshin 等）结果可解释**：Qwen2.5-1.5B-Instruct 对中文问卷能"逐题读题作答"，作答分布随题目变化，因此五种检索策略之间出现了**可区分的人格评测差异**。
- **英文角色（9 个，HP / 生活大爆炸等）作答退化**：同一主干对英文 BFI / 16Personalities 问卷**几乎恒答 "1"（strongly disagree）**——首 token 在 {1..5} 上的概率分布恒为 ≈[0.8, 0.15, 0.02, 0.01, 0.03]，与题目内容无关。我们测试了三种英文 prompt 变体（原始 / few-shot 示例 / 问题前置），均无法扭转这一塌陷。

我们确认这不是管线 bug：问卷英文文本完整（44/60 题均有 `rewritten_en`）、prompt 未被截断（`trunc=False`，问题在上下文内）、检索到的记忆随策略变化（见 §3.4 情感距离）。**根因是 1.5B 主干对英文 Likert 指令的跟随能力过弱**——这属于 §4 的 D1（骨干替换）范畴，是本地小模型而非方法本身的局限。因此下文把**中文结果作为可解释主结果**，英文结果单独列出并明确标注为"退化、不可用于策略结论"。

## 4. 差异归因

下面按"对最终指标影响从大到小"的顺序列出本次复现与原论文的所有系统性偏差。
其中 **D1 是量级上的唯一主导差异**，其余多为方法学或规模上的可解释差异。

### D1 — 骨干 LLM 替换（主导差异源）
| | 论文 | 本复现 |
|---|---|---|
| 模型 | ChatGLM3-6B / Qwen1.5-72B-Chat-GPTQ-Int4 / gpt-3.5-turbo-0125 | **Qwen2.5-1.5B-Instruct** |
| 显存占用 | — | 单卡 RTX 3060 Laptop 6 GB，无外部 LLM API |

论文在 InCharacter 上 BFI Acc(Dim) 最高 **0.726**（Qwen1.5-72B），最低 **0.624**（ChatGLM3-6B）。
本复现骨干仅 1.5B，且为指令微调版而非论文所用的 72B / 6B 基座，人格作答的"自我一致性"
显著更弱。这是 **Acc(Dim) / Acc(Full) 绝对数值整体低于论文、且情感策略增益被稀释** 的根本原因。
**结论：框架与协议可复现，但绝对精度受限于本地小模型，这是复现不可能完全对齐论文的核心约束。**

### D2 — 作答读取方式替换
| | 论文 | 本复现 |
|---|---|---|
| 作答 | 生成式自由作答后解析 Likert 数字 | **首 token Likert 分布期望值**（score_choices） |

直接 greedy 解码时，1.5B 骨干对全部 104 道问卷题都吐出同一个数字（实测恒为 "3"），
导致 5 种策略完全无法区分。改为"对候选数字 token 的首 token softmax 概率求期望值"后，
策略之间恢复了可区分的作答分布（见 §3.3 情感距离诊断）。这是一次**必要的工程修正**，
代价是绝对分数与论文的生成式口径不可直接比较。

### D3 — 情感向量 G 的估计器替换
| | 论文 | 本复现 |
|---|---|---|
| 情感向量 | GPT-3.5 + 情感提示词，对 8 维 Plutchik 各打 1–10 | **Go-Emotions 多语言分类器 → Plutchik 8 维映射**（默认回退到锚点通道） |

论文的情感向量依赖大模型按要求输出结构化 JSON。本地 1.5B 骨干在探针实验中
（见 `scripts/probe_prompt*.py`）无法稳定产出合法 JSON——要么复述提示词、要么立即 EOS，
所有向量退化为中性 `[5]*8`（std=0），会让 5 种检索策略在数学上完全等价。
因此用**预训练情感分类器**替代"大模型打分式 G"，输入输出契约（8 维、1–10）保持不变，
这正属于复现报告要量化的"估计器替换"类偏差。

### D4 / D5 — 数据集规模与覆盖
- 论文在 **32 个** InCharacter 角色上评测；本复现只覆盖其中 **15 个** 同时具备
  ChatHaruhi 记忆语料与 InCharacter 真人标注的角色（6 中文 + 9 英文）。
- 角色集合、问卷题项、真值标签全部来自 InCharacter 原始发布，评测口径一致；
  差异仅在样本量与语言分布（论文含更多英文/影视角色）。
- 小样本下 `Acc(Full)` 等细粒度指标方差更大，结论以 `Acc(Dim)` 与 `MSE/MAE` 为主。

### D6 — 记忆语料来源
论文使用 Character-LLM / ChatHaruhi 风格的角色记忆；本复现使用
`silk-road/ChatHaruhi-RolePlaying` 的 15 个角色 jsonl 记忆。记忆文本的分布差异
会间接影响检索到的 Top-10 质量，但对"五种策略相对 ordinary 的增益方向"影响有限。

### D7 — 人格评测协议已对齐官方实现（正向偏差）
本复现**没有**自行发明评测口径，而是严格复刻 InCharacter 官方 `personality_tests.py`：
反向题翻转、16Personalities 维度先做 `(score-1)/6*100` 归一、BFI 保留 1–5 原生均值、
分带规则 `H if score > range_middle else L`（16P 中值 50，BFI 中值 3）、
gold 真值中标记为 `X` 的维度在评测时跳过。这一步**消除了"评测实现不一致"带来的伪差异**，
使 D1/D2/D3 成为被观测到的真实差异来源。

### D8 — 多模态扩展（超出原论文的新增通道）
原论文只做文本情感（G）。本复现**额外**实现了一条语音声学情感通道
（HuBERT-SER + Windows SAPI TTS），作为"多模态情感理解"的落地扩展，详见 §5。
该通道在真实情感语音（RAVDESS）上有效，但在中性 TTS 合成的角色记忆上信息量不足——
这是扩展方法本身的局限，而非复现偏差。

## 5. 多模态扩展：语音声学情感通道

> 原论文的情感向量 `G` 是**纯文本**的。本复现额外实现了一条**语音声学情感通道**，
> 作为"多模态情感理解"的落地扩展——目标与手册主题（多模态情感理解）对齐。

### 5.1 架构（已实现、接线完整）

```
角色记忆 / 问卷文本 ──TTS(SAPI)──▶ wav ──▶ SER ──▶ Plutchik 8-d 向量 g_audio
                                                                 │
查询文本 ──(文本情感通道/锚点)──▶ g_text ──────────────────────────────┘
                                                                 ▼
                                        g = α·g_text + (1−α)·g_audio   (fuse)
                                                                 ▼
                                  直接喂入原论文的五种检索策略 C-A/C-M/S-S/S-E
```

- **文本通道**：锚点编码器（bge）或 Go-Emotions 分类器 → Plutchik 8-d（§4 D3）。
- **声学通道**：`text → Windows SAPI TTS → wav → SER(HuBERT) → Plutchik 8-d`。
  SER 取 `superb/hubert-base-superb-er`（在 IEMOCAP 4 类上微调），其 4 类后验经固定线性映射拼回 8 维。
- **融合**：`fuse(g_text, g_audio, α=0.5)` 得到单一 8-d 向量，复用了论文现有的全部策略，
  因此这是一条"真正独立的第二模态"而非对同一文本信号的重加权。

### 5.2 MM-1：声学通道在 RAVDESS 上的有效性（当前结论：未达可用）

RAVDESS 提供 8 类带标注的真实情感语音（neutral/calm/happy/sad/angry/fearful/disgust/surprised）。
用本地 HuBERT-SER 跑 MM-1 得到：

| 指标 | 数值 |
|---|---|
| 8 类 argmax 准确率 | 0.174（≈ 8 类随机水平 0.125） |
| 4 类 macro-F1 | 0.053 |

**诊断**：混淆矩阵显示该检查点对**全部片段**（含 happy/sad/calm）都恒定预测 `anger`，
原始 logits 中 `ang` 始终为正且最大、其余为负。我们已排除读取/归一化/标签映射等问题
（WAV 合法、RMS 随片段变化、id2label 对齐、do_normalize 无影响），结论是**该 4 类 IEMOCAP
检查点直接套到 8 类 RAVDESS 存在域/标签空间失配，本地副本表现脆弱**——这是扩展方法的
局限，而非管线 bug。

> 为获得可用的声学通道，已后台拉取在 RAVDESS 上训练的 8 类模型
> `audeering/wav2vec2-large-robust-12-ft-emotion-mmos`（angry/disgusted/fearful/happy/
> neutral/other/sad/surprised，与 RAVDESS 标注对齐）；到位后将以该模型重跑 MM-1/MM-2 并更新下表。
> 若拉取失败，本扩展以"架构就绪 + 文本通道机制已验证"的状态交付，声学通道列为待补强的已知短板。

### 5.3 MM-2：跨通道一致性（TTS 合成角色记忆）

MM-2 把角色记忆文本经 TTS 合成语音，再比较"文本情感通道"与"声学情感通道"对同一条记忆的
Plutchik 向量一致性（余弦 / 逐维 Pearson）。**前置依赖一个可用的 SER**，故在 5.2 的声学模型
就绪后一并给出；TTS 管线（Windows SAPI 单进程批合成）已实现。

### 5.4 已验证的多模态相关结论

即便声学通道待补强，**文本情感通道**已在本复现中证明有效（见 §3.4）：五种检索策略相对
ordinary 把查询与记忆的**平均情感距离降低 29%–53%**（中英文一致），且中文的人格准确率随之提升
（S-E 的 BFI Acc(Dim) 0.815 > ordinary 0.630）。这说明"把情感信号作为独立于语义的第二条检索通道"
这一**多模态式机制在本地可完整跑通并成立**——声学通道是其自然延伸。

## 6. 复现结论与可复用经验

### 6.1 复现结论（与 §0 呼应）

1. **框架与协议完整复现**：Emotional RAG 的全部组件——Plutchik 8 维情感建模 `G`、
   bge-base 语义编码 `F`、五种检索策略（ordinary / C-A / C-M / S-S / S-E）、Top-10 注入、
   BFI / 16Personalities 人格评测与 H/L/X 分带——均在本地无外部 API 的环境下跑通，
   且**评测协议严格对齐 InCharacter 官方实现**（§4 D7）。
2. **机制成立**：中文角色上，情感检索相对语义基线把**查询—记忆平均情感距离降低 29%–53%**，
   且人格准确率随之提升（S-E 的 BFI Acc(Dim) 0.815 > ordinary 0.630；C-A 的 MBTI Acc(Dim)
   0.682 > ordinary 0.455）——**论文"情感信号作为独立检索通道"的核心论点被本地验证**。
3. **绝对数值无法对齐，根因是骨干**：把 ChatGLM3-6B / Qwen1.5-72B / GPT-3.5 换成
   **Qwen2.5-1.5B-Instruct** 后，中文 ordinary 的 BFI Acc(Dim)=0.630 已接近 ChatGLM3-6B 论文值
   （0.624），但 MBTI Acc(Dim)=0.455 明显低于论文（0.669），且英文作答塌陷（§3.0）。
4. **语言不对称是真实发现**：同一 1.5B 主干对中文问卷能逐题区分作答、对英文问卷恒答 "1"。
   这是该小模型英文指令跟随的硬限制，不是管线 bug；已在 §3.0 明确区分中英文结果的可用性。

### 6.2 关键偏差一览（对应 §4）

| 编号 | 偏差 | 类型 | 对结果影响 |
|---|---|---|---|
| D1 | 骨干 1.5B 替换 6B/72B/3.5 | 主干替换 | **主导**：绝对精度下降、英文作答塌陷 |
| D2 | 首 token Likert 分布期望值（替 greedy） | 作答方式 | 必要修正，口径不可与论文直接比 |
| D3 | Go-Emotions/锚点 替 GPT-3.5 情感打分 | 估计器替换 | 契约不变，仅后端替换 |
| D4/D5 | 15/32 角色子集 | 数据规模 | 结论以 Acc(Dim)/MSE 为主 |
| D6 | ChatHaruhi 记忆语料 | 数据来源 | 对策略增益方向影响有限 |
| D7 | 对齐官方评测协议 | 正向 | 消除伪差异 |
| D8 | 多模态声学通道（扩展） | 新增 | 架构完整；本地 SER 待补强 |

### 6.3 可复用工程经验

- **小模型做 Likert 评测**：greedy 解码会让 1.5B 模型恒吐同一数字，必须改为**首 token
  分布期望值**（或 few-shot），否则五种策略在数学上等价。
- **小模型做结构化情感打分**：让它输出 8 维 1–10 的 JSON 会全部退化到中性；改用**预训练
  情感分类器 + 维度映射**（或锚点余弦）更稳，且契约不变。
- ** transformers ≥5 + torch 2.5 加载 `.bin` 被拒**：用 `convert_to_safetensors.py` 一次性转
  safetensors 绕过（CVE-2025-32434），无需升级 torch。
- **HuggingFace 主站不可达时用 hf-mirror**，并自写**可续传的字节区间下载器**（本仓库
  `scripts/` 下一组 fetch 脚本），因为镜像会限流/断流。
- **本地 6 GB 显存跑 1.5B**：`PYTORCH_CUDA_ALLOC_CONF=expandable_segments:true` + 只算
  最后一位 logits（`logits_to_keep=1`），否则 lm_head 对全序列展开会 OOM。

### 6.4 局限与后续

- **骨干**：若有 7B+/72B 或 API 主干，绝对精度与英文作答会大幅改善（预计接近论文）。
- **声学通道**：需一个在 RAVDESS 上训练的 8 类 SER（如 `audeering/wav2vec2-large-robust-12-ft-
  emotion-mmos`）替换当前 4 类 IEMOCAP HuBERT，才能使 MM-1/MM-2 真正可用。
- **数据**：扩到 InCharacter 全部 32 角色、并补齐英文角色的可用作答，可让结论更稳健。
